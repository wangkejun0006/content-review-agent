# 原应用脱敏改造范围

本版以固定的原应用源码快照为基线，在独立目录中修改；上一版精简实现已移入忽略的
恢复目录。没有修改来源仓库，没有复制其 Git 历史，也没有创建远程。

## 保留的原有结构与功能

- FastAPI、SQLAlchemy、Alembic 与 PostgreSQL 数据模型及迁移。
- Registry 类型、草稿/激活/退役版本、不可变快照、产品声明与证据关联。
- admin/editor/reviewer 身份和 API 权限校验。
- PostgreSQL Job Worker、领取/心跳/重试规则与 LangGraph Postgres Checkpointer。
- 产品/规则/趋势上下文、策略、三稿并行、合规子图、有限返工、评分推荐、人工审核。
- 发布登记、累计指标、更正快照、归因层级、反馈任务与待审核策略洞察。
- 原有 React/TypeScript 多页面运营台及测试。

上述代码来自原应用，不能把它们描述为本轮独立从零开发的贡献。

## 本轮修改

- 原商品资料、运营规则文件、品牌量表和暂存提取资料均不导入，改用虚构文具 fixtures。
- 替换源码示例中的公司/商品标识，产品分类调整为文具与桌面配件。
- 通过原领域服务初始化虚构品牌、三种角色、产品、合成证据和 Claim、Audience、
  内容模式、示例营销计划、洞察、Prompt、规则与评分量表。
- 修复 seed 幂等比较：先按正式 Payload Schema 归一化，再计算摘要。
- 模型端口增加 DeepSeek JSON Object 模式，仍由本地 Pydantic 验证完整契约。
- 增加跨进程请求次数硬上限、输出 token 上限与无网络自动重试模式。
- 本地演示入口默认关闭，仅专用启动器启用；不代表生产身份服务。
- API Key 从已有用户凭据文件读入进程内存，未写入仓库、数据库或日志。
- 数据库口令、JWT Secret 等本地运行秘密放在仓库外的用户私有临时目录。
- 原有模型设置功能保留，但本轮未将 API Key 保存为 Managed Provider。

## 验证中发现的问题

第一次真实调用发现虚构量表的 stable_key 与原流程要求不一致；修复后保留失败任务。
后续发现演示规则/语义提示把基础目录事实与效果 Claim 混淆，增加不必要返工。
修正原则是允许逐字引用冻结基础事实，效果声明仍必须有激活证据链；
并将虚构与 AI 辅助披露统一放在界面，避免生成与审查要求自相矛盾。
旧运行快照不重写，修复后的验证应创建新运行。

所有失败、预算停止和补充验证须分别记录，不用离线测试替代真实调用结论。
